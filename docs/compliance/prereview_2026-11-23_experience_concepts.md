## 0. どの案にも共通する前提（守ること）
| # | 前提 | 理由 |
|---|---|---|
| C-1 | **記録の中身（多い・少ない・食べなかった など）によって、猫の言葉・絵・表情・反応を変えない。** 変えてよいのは、日付・季節・時間帯・ランダム・飼い主さんの設定（毛色・名前）だけ | 中身で変わると、アプリが体調を評価したことになる（獣医師法・動物用医療機器プログラムの該当性、F-38 Won't、NFR-TONE）。良く見える反応も悪く見える反応も、どちらも評価になる |
| C-2 | **記録した・しなかったで、猫の様子を変えない**（しょんぼり・すねる・待っていた などを出さない。連続日数・ごほうび・解放されるアイテムも出さない） | 記録できない日の罪悪感（CLAUDE.md、F-30・F-31 の考え方）。介護がつらい時期ほど記録は途切れる |
| C-3 | **猫の言葉はすべて決まった文の一覧から出す。** 生成 AI で文を作らない | 自由に文を作ると、症状・治療・励ましの判定が混ざるのを防げない。一覧はロシアンのレビューを通す |
| C-4 | **「演出を控えめにする」（F-30）をオンにすると、会話・なでる反応・音・動き・日替わりの姿をすべて止め、今の落ち着いた入力画面で記録できる** | 介護の負担、見送りが近い時期、動きが苦手な人（前庭障害・光過敏）。今の入力画面は消さずに残す |
| C-5 | **見送り・一覧から外した猫では、会話・なでる反応・日替わりの姿・絵日記の自動作成・写真の自動表示をしない** | ペットロス（F-10）。亡くなった子が話しかけてくる・反応する、は深く傷つけるおそれがある |
| C-6 | **分析（K-3）で送るのは回数だけ。** 声の文字・写真・絵日記・会話の答えの中身は送らない | 決定済みの分析の範囲・恒久の約束「記録の内容を、広告に使うことはありません。」 |
| C-7 | 獣医師に見せるレポートには、会話・絵日記・今日の1枚を **載せない**（第1弾）。レポートは今の表のまま | レポートに演出が混ざると、獣医師が読みにくく、事実と演出の区別がつかない |

## 1. ④ 猫が話しかけてくる会話形式
### してよいこと
- 猫は **質問だけ** をする。質問は今の項目と同じ意味にする。例：「きょうのごはん、いつもとくらべて、どれくらい食べた？」「お水は、いつもとくらべて？」「おしっこは、なんかい？」
- 答えた後の言葉は、**どの答えでも同じ1種類** にする（または答えと無関係にランダム）。例：「おしえてくれて、ありがとう」「きろくしたよ」。
- 「とばす」「あとで」をいつでも選べ、その場合も同じ調子の言葉にする（「またあとでね」など）。

### してはいけないこと（線引き）
| 区分 | だめな例 | 理由 |
|---|---|---|
| 答えに応じた評価 | 「食べなかった」→「心配だね」「病院に行こう」、「いつもくらい」→「よかった！」「えらいね」「元気だね」 | 体調の評価・受診のすすめ（F-38 Won't、獣医師法の観点） |
| 飼い主さんへの評価・励ましの判定 | 「えらいね」「がんばってるね」「ちゃんと記録できたね」 | 記録した日だけほめると、できない日が責められているように感じる（C-2） |
| 猫が自分の体調・気持ちを語る | 「ぼく、きょうは元気だよ」「おなかすいた」「お水もっとほしい」「腎臓がんばってる」「どこもいたくないよ」 | 実際の猫の状態と無関係な言葉が、飼い主さんの判断に影響する。症状を打ち消すように聞こえると、受診が遅れるおそれ |
| 治療・食事への好き嫌い・おねだり | 「お薬いやだ」「補液こわい」「このごはん好き」「おやつちょうだい」 | 治療の継続に影響する。療法食から外れる行動を後押しする。特定の食品のすすめに見える |
| 記録しなかったことへの言葉 | 「きのうは来てくれなかったね」「さみしかった」「待ってたよ」 | 罪悪感（C-2） |
| 猫の判断が必要な質問 | 「痛そうだった？」「つらそう？」「脱水してる？」 | 飼い主さんに評価を求める・アプリが症状の見方を教える形になる。今の項目にない質問は足さない |
| 腎臓病・寿命に触れる | 「ずっといっしょにいようね」「長生きするね」 | 社外で使わないと決めた「長生き」と同じ。最期が近い時期に重い |

### そのほか
- 話す猫は、**案内役の猫（縁からのぞく猫）** にするのを推奨する。飼い主さんの猫そのものの声として話させる場合は、「名前を呼ぶだけ」にとどめ、猫の一人称で体や気持ちを語らせない（上の表）。
- 通知（F-24・F-31・F-32 など）は、今の決まった文のままにし、猫の口調にしない（ロック画面に出るため、内容を隠す設定 F-24 とも合わない）。
- 法令の整理：上の線を守れば、会話は **入力の見た目を変えただけ** で、診断・評価をしていないという整理（NFR-REG-06）は変わらない。答えで言葉が変わる設計にすると、この整理が崩れる。

## 2. ⑥ 声で記録（端末内の音声認識）
| # | 条件 | 理由・補足 |
|---|---|---|
| V-1 | **端末の中だけで認識する設定を必ず使う。** 端末内で認識できない機種・言語設定では、声の記録を出さない（「この端末では使えません」と表示） | iOS・Android とも、設定によっては音声が OS 事業者のサーバーに送られる仕組みがある（**未確認**：iOS の Speech フレームワークの端末内認識の指定、Android の端末内認識の API と対応機種。マンチカンが公式資料で確認し、結果を残す） |
| V-2 | **録音を保存しない。** 認識に使った音声は、認識が終わったらすぐ捨てる。文字にした結果も、下書きを作った後は保存しない（飼い主さんがメモ欄に入れた場合を除く） | 個人情報の最小化。家族の会話など、関係ない声が入る |
| V-3 | **声から作るのは下書きだけ。** 画面に「下書き」の印を付け、飼い主さんが見て直してから保存する（F-33・F-37 と同じ考え方）。保存前の値で、お知らせ（F-27・F-31）を動かさない | 聞き違い（「20」と「200」、「1回」と「いっかい」の取り違え） |
| V-4 | **数の聞き違いに特に注意する。** 補液の mL・体重は、数字を大きく表示して確認させる。入力ミス防止の上限（F-04）は、声でも同じに働かせる | 補液の量の取り違えは安全に関わる |
| V-5 | **決まった言葉だけを項目に当てはめる。** 「食べなかった」「いつもくらい」「2回」など。「ぐったり」「元気ない」「なんか変」などの言葉から、元気さや食欲の段階を **推し量らない**（空欄のままにし、メモに残すかを飼い主さんが選ぶ） | 言葉の意味を読み取って体調の段階を決めると、アプリが評価したことになる |
| V-6 | マイクは **ボタンを押している間・押した後の短い時間だけ** 使う。常に聞いている状態・呼びかけで起動する機能は作らない。使っている間は分かる表示を出す | プライバシー。OS の権限の説明文（マイク・音声認識）に「記録の下書きを作るためだけに使い、録音は保存しません」と書く |
| V-7 | プライバシーポリシーとストアのプライバシー申告に、マイク・音声認識の使い方を書く。端末の外に出ないなら「収集しない」になるが、V-1 の確認結果に合わせて書く | 申告と実際の動きの一致（NFR-PRV-05） |
| V-8 | 分析で送るのは「声の記録を使った回数」まで。認識した文字は送らない | C-6 |

## 3. 今日の1枚（写真、端末の中だけ）
### F-37 との関係
- 今日の1枚は **思い出として残すだけの写真** で、F-37（物の写真から回数・量の下書きを作る、第2弾）とは **別の機能** にする。
- 今日の1枚の写真を、**解析しない**（体型・表情・毛づや・姿勢などを読み取らない。自動でタグや説明を付けない）。将来 F-37 を作るときも、今日の1枚の写真を入力に使わない。猫の体・顔・姿勢からの推し量りは Won't（決定済み）。
- 写真に、体調の段階・その日の記録の中身を重ねて表示しない（「食べた量：少ない」の文字を写真に載せる など）。

### 保存・書き出し・機種変更
| # | 条件 | 理由・補足 |
|---|---|---|
| P-1 | 写真はアプリの中だけに保存し、**端末の写真アプリに自動で保存しない**（飼い主さんが「写真に保存」を押したときだけ） | 勝手に写真アプリが増えない |
| P-2 | 写真の選択は、OS の写真選択画面（写真ライブラリ全体へのアクセスを求めない方式）を使う。カメラの権限の説明文に目的を書く | 権限の最小化 |
| P-3 | **位置情報（撮影場所）を取り除いて保存する。** 書き出し・共有のときも付けない | 自宅の場所が分かる |
| P-4 | 端末の中だけなので、**機種変更や削除で消える** ことを、最初に写真を残すときに一度だけ伝える。書き出し（写真アプリへの保存・まとめて保存）の方法を用意する | 「消えるとは知らなかった」が、見送った後に起きると取り返しがつかない |
| P-5 | 端末のバックアップ（iCloud・Google）に含まれるかどうかは、**実装で確認して** プライバシーポリシーに書く（未確認） | 「端末の中だけ」と言い切れるか |
| P-6 | 猫を削除したときの写真の扱い（一緒に消す、確認してから消す）を決める。**見送り・一覧から外した猫の写真は、消さずに残し、飼い主さんが開いたときだけ見られる** | ペットロス |
| P-7 | **「1年前の今日」のような、過去の写真を自動で出す機能は作らない**（少なくとも見送った猫には出さない。出すなら設定でオンにした人だけ） | 予期しない場面で亡くなった子の写真が出ると、深く傷つける |
| P-8 | 写真は、獣医師に見せるレポート・CSV に入れない（第1弾。C-7） | — |
| P-9 | SNS への共有ボタンを付ける場合、アプリ名・ロゴの透かしや宣伝の文を自動で入れない。共有は飼い主さんが選んだときだけ | 飼い主さんの投稿がアプリの広告に見えないように |

## 4. ③ 絵日記（記録から自動で描く1コマ）
| # | 条件 | 理由 |
|---|---|---|
| D-1 | 1コマの絵は、**記録の中身で変えない**（C-1）。食べなかった日に寝ている絵・しょんぼりの絵、いつもくらいの日に遊ぶ絵、のような対応を作らない | 体調の良し悪しを示すことになる |
| D-2 | 絵に出してよいのは、**何を記録したか（体調・補液・お薬のアイコン）という事実** と、日付・季節・天気（飼い主さんが選ぶ）・ランダムな背景だけ | 事実の範囲にとどめる |
| D-3 | 絵日記に、自動で文を付けない（「きょうは元気だったね」「よく食べたね」など）。付けるなら、飼い主さんが書いたメモだけ | 評価の言葉になる |
| D-4 | **記録しなかった日を、空白・灰色・しょんぼりで見せない。** その日のページを出さないか、何もない同じ見た目にする。連続日数・ページ数の達成を出さない | C-2 |
| D-5 | 下書き（前回の内容・声の下書き）は、保存するまで絵日記に反映しない | 実際に記録していないものが残る |
| D-6 | 見送った猫の絵日記は、新しいページを作らず、今までのページは残す。記念日の通知を出さない | C-5 |

## 5. 毎日ちがう猫の姿・なでると反応・音と手ざわり
| # | 条件 | 理由 |
|---|---|---|
| A-1 | 日替わりの姿は、**日付・季節・時間帯・ランダムだけで決める。** 記録の有無・中身では変えない（C-1・C-2） | 「記録した日は元気な姿、しなかった日は寝ている姿」は、評価と罪悪感の両方になる |
| A-2 | 姿の一覧に、**具合が悪そうに見える姿を入れない**（背中を丸めてうずくまる、ぐったり横たわる、目を細めて耐えている、毛を逆立てる、吐く など）。眠る・香箱・毛づくろい・のび など、ふだんの穏やかな姿だけにする | 体調を示しているように見える。CKD の猫の飼い主さんには、実際の症状を思い出させる |
| A-3 | なでたときの反応は、**いつも同じ種類の穏やかな反応**（目を細める・しっぽをゆらす など）。そっぽを向く・逃げる・怒る反応は作らない。なでた回数で反応を強くしない | すねる反応は罪悪感、回数で変わるのはゲーム化 |
| A-4 | 音は **初期値オフ**、または端末の消音・マナーモードに必ず従う。夜間（例：22時〜7時）は鳴らさない。振動（手ざわり）も F-30 で止められる | 夜間の介護・通院の待合室・見送り後 |
| A-5 | 点滅・速い動き・画面全体のフラッシュを使わない。OS の「視差効果を減らす」設定に従う | 光過敏・動きによる酔い（F-29・F-30） |
| A-6 | なでる対象を飼い主さんの猫そのもの（毛色・名前つき）にする場合、見送り・一覧から外した猫では反応させない（C-5） | ペットロス |

## 6. ① 猫の部屋をタップして記録／② 1問1枚のカード（参考）
- ①：部屋の物（器・水飲み・トイレ など）を、**記録の入口** として使うのは問題ない。ただし、部屋の様子を記録の中身で変えない（食べなかったと記録したら器が満杯のまま、記録しないとトイレが汚れたまま、のような表現は作らない）。C-1・C-2 と同じ。
- ②：1問1枚でも、**とばす・途中で保存** をいつでもできるようにする。全部答えないと保存できない形にしない。今の「1つ入力すると保存できる」を保つ。答えを選んだ直後に自動で次へ進む場合、選び直しが簡単にできるようにする（誤タップのまま記録されるのを防ぐ）。

## 7. 見本ができたら見ること（予告）
1. 猫の言葉の一覧（すべての文）と、どの場面で出るか
2. 声の記録：端末内認識の確認結果（OS・ライブラリの資料）、権限の説明文、下書きの見せ方
3. 今日の1枚：位置情報の除去、機種変更の案内、見送り時の扱い
4. 絵日記・日替わりの姿：絵の一覧と、何で変わるかの対応表（記録の中身と無関係であること）
5. F-30（演出を控えめにする）をオンにしたときの画面
6. 要件への反映（ブリショー）：新しい体験は、要件の F 番号と Must/Could を決めてから製品版に入れる

## 判定
**事前確認のため、判定なし**（線引きの提示）。上の C-1〜C-7 を守れば、どの案も法令・医療面で作ってよい方向です。特に重いのは **C-1（記録の中身で反応を変えない）** と **C-5（見送った猫に話させない・反応させない）**、声の記録の **V-1（端末の中だけ）** です。
