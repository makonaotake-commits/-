## 1. 確認した点
| 項目 | 状態 | 判定 |
|---|---|---|
| 変えてよいきっかけ | 日付・季節・時間帯・天気・ランダム・飼い主さんの操作だけ。記録の中身・有無では変えない、と明記 | ✅ C-1・C-2 |
| 姿5つ（すわる・香箱・のびる・のぞく・窓の外） | どれも目を開けたおだやかな姿。うずくまる・ぐったり・目を閉じて横たわる姿はない。「寝ている」も目を開けて丸まる姿 | ✅ A-2 |
| なでる反応 | 目を細める・ごろごろの弧・しっぽを1回ゆらす（1.6秒以内）だけ。そっぽ・逃げる・怒るはない | ✅ A-3 |
| 部屋の家具 | 器の粒はいつも同じ量の飾り。トイレの様子も変わらない | ✅ §6 ① |
| 話しかける猫 | 案内役（guide_peek）を使う。どの質問でも同じ顔 | ✅ §1 |
| 動き・F-30・見送り | 点滅なし。F-30 または OS の動きを減らす設定で止まった絵1枚。見送った猫は対象外 | ✅ C-4・C-5・A-5 |
| 夜の窓（暗い空） | 時刻で変わるだけ。不安をあおる表現ではない | ✅ |

## 2. 指摘
| # | 箇所 | リスク区分 | 重大度 | 問題点 | 修正案 |
|---|---|---|---|---|---|
| E-1 | 絵日記：その日に記録した「項目」で1コマ（`diary_meal`・`diary_drink`）を選ぶ | 獣医学的正確性・表現（ペットロス） | **中** | 項目で選ぶこと自体は「何を記録したか」という事実なので、D-2 の範囲。ただし `diary_meal` は**猫がごはんを食べている場面**。「食べなかった」と記録した日にも、食べている絵が残る。中身と食い違う絵日記は、①あとで見返したときに「この日は食べていた」と思い違いをさせる、②食べなくなった時期の飼い主さんには、つらい絵になる。`diary_drink` も同じ | 次のどちらかにする。**A（推奨）**：1コマの場面は日付・ランダムで選び（rest・window など、食べる・飲むを描かない場面）、その日に記録した項目は、コマの隅の小さなアイコン（体調・補液・お薬）だけで示す。**B**：項目で選ぶ場合は、食べる・飲む動作を描かない絵に変える（器の横にすわっている・器だけ、など） |
| E-2 | 窓の天気：「端末の天気情報」を使う | 個人情報 | 低〜中 | 端末の天気情報を使うには、**位置情報の権限**や外部の天気サービスへの通信が必要になる。「記録は端末の中だけ」「権限は最小限」の方針と合わず、プライバシーポリシー・ストアの申告にも影響する | 天気は **季節に合わせたランダム** だけにする（位置情報を使わない）。使うなら、飼い主さんがその日の天気を選ぶ形にする |
| E-3 | 部屋：器をタップすると猫が `cat_eat` で食べる | 表現 | 低 | 器のタップは記録の入口。「食べなかった」を記録しに来た飼い主さんの前で、猫が食べる動きをするのは、E-1 と同じ食い違い・つらさになる | タップした場所へ歩いて、器の横に**すわる**（`pose_sit`）にする。食べる・飲む動作は使わない |
| E-4 | 絵日記の「記録しなかった日」・下書き・見送り | 実装（マンチカン） | 低 | 表には書かれていない | アプリ側で、D-4（記録しなかった日を空白・灰色・しょんぼりで見せない、連続を出さない）、D-5（下書きは保存するまで反映しない）、D-6（見送った猫は新しいページを作らない）を守る。マンチカンに伝える |

## 3. 判定
**修正後OK**（E-1・E-2 を直せば OK。E-3 は推奨、E-4 はアプリ側で対応）。絵そのものに、具合が悪そうな姿や良し悪しを示す表情はなく、線引きに合っています。
