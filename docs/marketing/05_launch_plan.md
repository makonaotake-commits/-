## 4. 予算と体制（確定）と、作業量の見直し

## 5. リスクと対策

| リスク | 対策 |
|---|---|
| ユーザー本人が「開発」「画像制作」「監修獣医師としての確認」「投稿の最終承認」を兼ねるため、確認待ちや制作が詰まる【推測】 | §4-1 の最小構成にする。確認は週1回にまとめ、12 月中に4週分をためる。開発が詰まった週は投稿を1本に減らしてよい（**休んでも責めない運用**を自分たちにも適用する） |
| 開発が遅れて、猫の日に間に合わない | 猫の日を「事前登録のお知らせ」に切り替える。世界腎臓デーをリリースの山にする |
| 投稿の承認待ちで、週2〜3本を維持できない | 2 週間分を先にためておく。レビューの締め切りを決める（スコティ・ロシアンと相談） |
| ローンチ時に、ニュース（新薬など）や悲しい出来事が重なる | 予約投稿の一斉停止の手順（ロシアン D-5）を使う |
| 見送った飼い主さんに、再勧誘やレビュー依頼が届く | 見送った猫が1匹でもいる人を、すべての再勧誘・アンケート・レビュー依頼の対象から外す。第1弾で見送り機能がない場合は、これらを第1弾では一切行わない（`03` §2・§7、`04` §0） |
| 闘病中の飼い主さんから個別相談が殺到する | 定型文（ロシアン C-2）を、ローンチ前に用意する |
