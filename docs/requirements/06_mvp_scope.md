### 範囲

| 区分 | ID | 機能 | 備考 |
|---|---|---|---|

### 追加・変更の根拠

| # | 変更 | 根拠 |
|---|---|---|
| 1 | **F-10 お休み・見送りモードを Must に追加** | 第1弾にリマインダーがある以上、見送った子への通知を確実に止める手段がないと、ペットロスへの配慮（最重視の要望）に反する。ペルソナ C（高齢猫）の想定にも直結する |
| 2 | F-08 振り返り（編集・削除）を追加 | 記録を直せないと、レポートの内容が不正確になる。最低限の確認・修正手段が必要 |
| 3 | F-09 書き出し・削除、F-01 同意を追加 | 個人情報の取り扱い（削除・持ち出し）と、免責の表示のために、リリース時に必須 |
| 4 | F-12 体重グラフを Should に追加 | 体重は第1弾の体調記録に含まれていて、推移は診察で見せたい情報の代表。検査値グラフ（第2弾）と同じ部品を先に作れるため、第2弾の負担も減る（推測） |
| 5 | F-06 リマインダーを明記 | 仮案の「皮下輸液」「投薬」が記録だけか、通知も含むかがあいまいだったため、通知を含むと明記した |
| 6 | 薬の候補リストは入れない | 正確な保守のコストがかかり、特定の薬をすすめているように見えるリスクもあるため（⚠️ → `07` の Q-09） |

### 第1弾に入れないもの
- 療法食・フード量（F-14）、写真（F-15）、検査値（F-16）、本格的な通院予定（F-17）→ **第2弾**
- 家族共有（F-18）→ **第3弾以降**
- 広告枠（F-20）→ **未決**（→ `07` の Q-02）。入れる場合も、記録画面とは別の「おしらせ」タブだけに表示する
- 学習コンテンツ（F-19）→ 未定
- 動物病院との連携（F-21）、判定・提案（F-22）→ **作らない**

### 規模感についての注意（推測）
- 上記は、3か月で両 OS に出すには **余裕のない範囲** と見ています（開発体制が未確定のため推測）。
- 削る順番の案：① F-13 通院日メモ → ② F-12 体重グラフ（PDF の一覧表だけにする） → ③ CSV の書き出し（全削除は残す）
- **F-10 見送りモード、F-01 免責・同意は削らない** でください。

## 4. リリース計画（仮）

> 期間はすべて **仮** です。開発体制（社内か外注か・人数）が決まった時点でボンベイと見直します（→ `07` の Q-13）。

| 時期（目安） | 内容 | 関わる猫・人 |
|---|---|---|
| 1〜2週目 | 要件の確定（本書の未決事項の回答）、ロシアンによる要件レビュー、画面のラフ | ブリショー、ロシアン、ユーザー（監修獣医師） |
| 2〜4週目 | デザイン（ラインアート・トーン）、主要画面のプロトタイプ、飼い主さん数名に見てもらう（仮） | デザイナー（未定）、ユーザー |
| 3〜10週目 | 第1弾の開発 | 開発チーム（未定） |
| 8〜11週目 | 文言の最終レビュー（画面・通知・PDF・ストアの説明文・プライバシーポリシー） | ロシアン、ユーザー |
| 10〜12週目 | テスト（多頭飼い・見送りモード・オフライン・文字サイズ特大）、ストア申請 | 開発チーム |
| 12週目まで | **第1弾リリース** | — |
| 第1弾の後 | KPI の確認 → 第2弾の要件の詳細化 | ブリショー、ベンガル |

### 第1弾のリリース条件（Definition of Done・仮）
- [ ] 第1弾の Must 機能が、iPhone と Android の両方で動く
- [ ] 飼い主向けの全文言が `compliance_reviewed` になっている
- [ ] ⚠️ の付いた機能（F-04, F-05, F-07, F-12）について、ロシアンの確認が終わっている
- [ ] 見送りモードで、その猫の通知がすべて止まることをテストで確認した
- [ ] 文字サイズ「特大」で、主要画面の表示が崩れない
- [ ] プライバシーポリシー・利用規約・ストアのプライバシー申告が、実際の動作と一致している
