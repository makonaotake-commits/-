### Q-27b で記録の種類を送る場合の条件（ロシアン KPI レビュー `docs/compliance/review_2026-11-10_kpi_analytics.md`）
1. 種類は **固定の3つ（体調・補液・投薬）だけ**。補液の量・部位、薬の剤形、体調の項目名（嘔吐など）は送らない。
2. **1日単位で端末内で集計** し、「日付・種類・件数」として送る（記録した時刻の細かい並びは送らない）。
3. ユーザーを識別するのは、アプリが作る **ランダムな ID だけ**。広告 ID・端末 ID は使わない。
4. 分析 SDK は、広告やほかのアプリのデータと結び付ける機能を持たないもの、またはその機能を無効にできるものを選ぶ。SDK 一覧（NFR-PRV-05）に、送信先の国と、提供者によるデータの使い方を書く。
5. 設定画面とプライバシーポリシーに、種類を送ることを明記する。案：「アプリの使われ方（記録の種類〔体調・補液・投薬〕と件数など）を、改善のために送ります。記録の中身（値・お薬の名前・メモ）は送りません。」
6. **お休み中・一覧から外した猫の記録は、分析の対象にしない**（イベントもフラグも送らない。NFR-PRV-11）。
- 種類を送らない場合は、「記録を保存した」だけを送り、K-4 の内訳は聞き取りで補う（Q-27b）。
- 条件③（ランダムな ID）・④（結び付けない SDK）・⑥（お休み中・一覧から外した猫は対象外）は、種類を送るかどうかにかかわらず守る。分析は初期値オンのため、初回設定での案内（K-3）は必須（NFR-PRV-12）。

### Q-29 についてのブリショーの見立て
- **★ベータ版だけに入れる理由**：①聞き取りの協力者（5〜10人）が数値を見て答えられれば、分析なしでも K-1・K-3・K-4・K-5 の目安がつかめる。②製品版で全員に見せると、「記録日数」が成績のように感じられ、せかさない・責めないという方針（NFR-TONE-02、`02` の「設計上の約束」）とぶつかるおそれがある。③表示するだけで外部には送らないので、プライバシーの負担は増えない。④ Expo では、ベータ版と製品版で表示を切り替えるのは小さな作業で済む（**推測**。開発担当に確認する）。
- **入れる場合の表示ルール（案）**：件数を事実として並べるだけにし、目標・達成率・連続記録日数・ランキング・色での評価・「がんばりましょう」などの言葉は出さない。猫の体調の値は集計しない（記録の件数だけ）。見送り・お休み・一覧から外した猫の件数は、ほかの猫と並べて比べない。
