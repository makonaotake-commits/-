# 07 確認事項・リスク

- 作成：ブリショー ／ 版：初版（2026-11-09）
- 「仮」で置いた点の一覧です。ボンベイが選択肢つきのシートにしてユーザーに確認します。★ はブリショーのおすすめです。

---

## 1. ユーザーに確認したいこと

| ID | 論点 | 選択肢（★おすすめ） | 影響 | 関連 |
|---|---|---|---|---|
| Q-01 | 第1弾の範囲（`06` の最終案）でよいか | ★ブリショー案（ボンベイ案＋見送りモード・振り返り・書き出し・体重グラフ）／ボンベイ案のまま／さらに絞る | 開発規模 | `06` |
| Q-02 | 第1弾から広告を出すか | ★第1弾は広告なし（利用者を増やし、表示ルールを固めてから第2弾で）／第1弾から「おしらせ」タブだけに出す | 収益の開始時期、ロシアンの確認範囲 | F-20, NFR-ADS |
| Q-03 | 猫の記録データを広告に使うか | ★使わない（記録内容に連動した広告も出さない）／同意した人だけ使う | 同意画面の設計、信頼感 | NFR-PRV-03, NFR-ADS-04 |
| Q-04 | データの保存先 | ★第1弾は端末内保存＋書き出し（アカウント不要）／最初からクラウド保存（アカウント必要） | 機種変更時の引き継ぎ、家族共有（第3弾）への移行、開発量 | F-01, F-09 |
| Q-05 | 監修獣医師（ユーザー本人）の開示方法 | ★アプリ内「このアプリについて」とストアの説明文に、氏名・資格・運営者であることを記載／氏名は出さず「獣医師監修」とだけ記載 | 信頼感、利益相反の見え方（広告との関係） | NFR-REG-03 |
| Q-06 | 体調記録の項目と段階の言葉 | ★ `04` の F-03 の案で、監修獣医師が言葉を直す／項目を増やす・減らす | 記録の続けやすさ、レポートの有用性 | F-03 |
| Q-07 | 猫の登録時に「病名・ステージ」を入れる欄を作るか | ★作らない（メモ欄に自由に書ける）／任意の入力欄を作る（表示だけで、アプリの動作には使わない） | ⚠️ ステージを前提にした振る舞いと誤解されないか | F-02 |
| Q-08 | 補液量の入力ミス防止の上限 | ★上限値は監修獣医師が決め、文言はロシアンが確認／上限チェックはしない | ⚠️ 安全性と、医学的評価に見えるリスクのバランス | F-04 |
| Q-09 | 薬・療法食の候補リスト（製品名の選択肢） | ★第1弾・第2弾とも自由入力のみ／候補リストを作る（広告主の製品を優先しない） | ⚠️ 推奨と誤解されるリスク、保守の負担、中立性 | F-05, F-14 |
| Q-10 | レポートに入れる集計値 | ★記録日数・回数の合計など「事実の集計」だけ／平均・増減も入れる | ⚠️ 解釈・判定と受け取られないか | F-07 |
| Q-11 | 見送りモードの言葉と、思い出画面の扱い | ★監修獣医師とロシアンで文言を決める。お悔やみは控えめにする／見送り機能は第2弾に回す（非推奨） | ペットロスへの配慮 | F-10 |
| Q-12 | KPI の目標値 | ★ベンガルが市場データをもとに案を出す／ユーザーが決める | 成功の判断 | `01` の §6 |
| Q-13 | 開発体制・技術・対応 OS の範囲 | 社内／外注／未定（★まず見積もりを取る） | リリース計画（`06` の §4）が仮のままになっている | NFR-ENV |
| Q-14 | 家族共有がない第1弾で、夫婦で記録する家庭の扱い | ★1台を共有して使う前提で案内する／第1弾に簡易的な共有（書き出しの受け渡し）を入れる | ペルソナ B の満足度 | F-18 |

## 2. ロシアンに確認したいこと（⚠️）

| ID | 確認内容 | 関連 |
|---|---|---|
| R-01 | 記録と見える化だけの設計（判定・提案・基準値表示なし）で、獣医師法の「診療」と、動物用医療機器プログラムのどちらにも当たらないと整理できるか | 全体 |
| R-02 | 補液量の入力上限チェックと、その表示文言が、医学的な評価に当たらないか | F-04 |
| R-03 | 二重投与防止の「記録済みです」の表示が、判断・警告に当たらないか | F-05 |
| R-04 | レポート（PDF）の構成と集計値の範囲。注記の文言 | F-07 |
| R-05 | 体重グラフ・検査値グラフ（第2弾）で、基準線を引かない方針で十分か。単位の扱い | F-12, F-16 |
| R-06 | 療法食・フードの広告の表示ルール（薬機法〔動物用〕・景品表示法・ペットフードの表示）、「広告」表示の方法 | NFR-ADS |
| R-07 | 猫の健康データの個人情報としての位置づけ（要配慮個人情報に当たるか）と、同意・プライバシーポリシーの内容 | NFR-PRV |
| R-08 | 監修獣医師が運営者でもあることの開示方法 | NFR-REG-03 |
| R-09 | 見送りモード・通知・初回設定など、飼い主向け文言の全体 | F-01, F-06, F-10 |

## 3. リスク

| ID | リスク | 重大度（仮） | 対策 |
|---|---|---|---|
| RISK-01 | 3か月で両 OS に第1弾を出すには、範囲に余裕がない（推測） | 高 | `06` の「削る順番」を事前に合意する。体制を早く決める（Q-13） |
| RISK-02 | 表示や文言が「判定」と受け取られ、獣医師法・医療機器に関わる | 高 | NFR-REG-01・02。⚠️ 機能は着手前にロシアンが確認する |
| RISK-03 | フードメーカーの広告で、アプリの中立性・信頼感が損なわれる | 中〜高 | 記録画面との分離、記録データを広告に使わない、候補リストで優先表示しない（Q-02, Q-03, Q-09） |
| RISK-04 | 見送ったあとに通知が届くなど、ペットロスの悲しみを深めてしまう | 高 | F-10 を第1弾の Must にする。テスト項目に入れる |
| RISK-05 | 端末内保存だけの場合、端末の故障・紛失で記録が失われる | 中 | 書き出し（F-09）と、OS のバックアップの案内。クラウド化の検討（Q-04） |
| RISK-06 | 多頭飼いでの記録の取り違え | 中 | 記録画面での猫の常時表示、まとめて記録しない（F-02） |
| RISK-07 | 監修獣医師が運営者を兼ねることによる、利益相反の見え方 | 中 | 開示（Q-05, R-08） |
| RISK-08 | ペルソナや KPI が推測ベースで、実際の飼い主さんの声で検証されていない | 中 | 2〜4週目に、飼い主さん数名にプロトタイプを見てもらう（`06` の §4） |

## 4. 他の猫への申し送り
- **ベンガル**：KPI の目標値（Q-12）、広告の開始時期と収益の見込み（Q-02）、監修獣医師の開示の見せ方（Q-05）
- **ロシアン**：上の R-01〜R-09。特に R-01 と R-06 を優先
- **スコティ**：アプリの紹介投稿では、「判定しない・記録のためのアプリ」という位置づけと、`05` の NFR-TONE（せかさない・責めない）に合わせる
