# 04 機能要件

- 作成：ブリショー ／ 版：第3版（2026-11-10 更新。「要件定義の確認シート」「開発の進め方シート」の回答と、ロシアンの第3版レビューを反映） ／ レビュー状態：`compliance_reviewed`（第3版。ロシアン 2026-11-10 → `docs/compliance/review_2026-11-09_requirements_v3.md`）
- 優先度：MoSCoW（Must / Should / Could / Won't）
- リリース：**第1弾**（3か月以内）／**第2弾**／**第3弾以降**（→ `06_mvp_scope.md`）
- ⚠️ ＝ 獣医師法（診療行為）または動物用医療機器プログラムに関わる可能性があり、**ロシアンの確認が必要** な機能・仕様

## 全機能に共通する原則
1. **記録と見える化だけ**。判定・評価・提案・基準値との比較はしない（`kickoff_answers.md` #2）。
2. 補液量・薬・フード量などの「値」は、**飼い主さんが獣医師の指示をもとに自分で入力** する。アプリが初期値や推奨値を入れることはしない。
3. 入力負荷を最小にする：ワンタップ、前回コピー、時刻の自動入力、片手操作。
4. 文言はロシアンのレビュー（`compliance_reviewed`）を通してから公開する。

## 2. 機能詳細（第1弾）

### F-01 初回設定・ご利用にあたって
- 最初の起動時に、短い3画面だけを表示する。
  1. このアプリでできること：記録とまとめ
  2. できないこと：診断・判定・治療の提案はしない。**かかりつけの獣医師の指示を優先**
  3. データの扱い：保存場所と、記録データを広告に使わないこと
     - **Q-03 が決まるまで、この画面の文言は確定しない**（ロシアン #17）。
     - 「使わない」に決まった場合：F-01・プライバシーポリシー・ストアのプライバシー申告の3つで **同じ表現** にし、外部 SDK にも送らない。将来方針を変える場合は、改めて同意を取る。
     - 「同意した人だけ使う」に決まった場合：利用規約とは別のオプトイン画面を作る（初期値オフ、同意しなくても全機能を使える、いつでも撤回できる、利用目的を「どのデータを・何のために」まで具体的に書く、広告主には集計データだけを渡す）。
- 利用規約とプライバシーポリシーへの同意。
- アカウント登録なしで始められる（仮。`07` の Q-04）。
- 緊急時の一般的な一文を置く（F-11 の設定画面にも置く）。案：「急に様子が変わったときは、記録より先に、かかりつけの動物病院にご相談ください。」 症状ごとの「すぐ受診」リストは第1弾では作らない（ロシアン #19）。
- 文言はロシアンのレビュー対象。

### F-02 猫の登録・多頭飼い
- 登録は **名前だけで完了** する。写真・生年・性別・メモは任意で、あとから追加できる。
- 第1弾では、病名・ステージの入力欄は **設けない**（仮）。メモ欄に自由に書ける。第2弾で「獣医師から伝えられたステージ」の任意入力欄を、検査値（F-16）と一緒に設ける。アプリの動作には使わない（ロシアン A-1、`07` の Q-07）。入力欄の近くに「獣医師から伝えられたものを記録する欄です」と添える。ステージによって表示・通知・広告を変えないことを、受け入れ条件に入れる（ロシアン #22）。
- 登録できる頭数は10匹まで（仮）。
- 猫の切り替え：画面上部に猫のアイコンを並べ、1タップで切り替える。記録画面では、今どの子を記録しているかを常に名前と写真で表示する（取り違え防止）。
- 1回の操作で複数の猫にまとめて記録はしない（取り違えを防ぐため。仮）。

### F-03 毎日の体調記録
- 項目と入力方法（仮。最終的な項目と段階の言葉は、監修獣医師〔ユーザー〕の確認が必要 → `07` の Q-06）

| 項目 | 入力方法 | 備考 |
|---|---|---|
| 食欲 | 3段階：いつもより少ない／いつもくらい／いつもより多い ＋「食べなかった」 | 評価語（良い・悪い）は使わない |
| 飲水 | 3段階：少ない／いつもくらい／多い。任意で mL | |
| 尿 | 回数（＋／−ボタン）。任意で、塊の大きさを3段階 | |
| 嘔吐 | 回数（＋／−）。任意でメモ・時刻 | |
| 便 | 回数（＋／−）。任意で状態（かたい／ふつう／やわらかい） | |
| 元気さ | 3段階：いつもより静か／いつもくらい／いつもより活発 | |
| 体重 | kg、小数第2位まで（例：3.45） | 入力欄は空欄で始める。前回の値は「前回 3.45 kg（11/8）」と **日付つきの参考** として表示する。「前回と同じ」で体重をコピーして保存した記録には、コピーの印を付ける（ロシアン v2 再レビュー B） |
| メモ | 自由入力 | |

- **1項目だけでも保存できる**。全部埋める必要はない。
- 「前回と同じ」ボタン：直前の記録を、今日の記録としてコピーする。コピーして直さずに保存した記録には、内部で「コピー」の印を付ける（ロシアン #2。レポートでの見せ方は F-07）。
- 記録日時は自動で入り、あとから修正できる。
- 入力値に対して、判定・コメント・色分けを表示しない。

### F-04 皮下輸液の記録 ⚠️
- 項目：実施日時（自動）、量（mL）、部位（任意）、様子（スムーズ／少し嫌がった／途中でやめた）、メモ。
- **部位（任意）**（ロシアンのマーケレビュー #8 を受けて追加 → `07` の Q-23）
  - 選択肢（仮）：首の後ろ〜肩のあたり／背中／腰のあたり／その他、＋ 左・右・中央（任意）。最終的な選択肢は監修獣医師が決める。
  - 前回の部位を「前回：背中・右（11/8）」と表示するだけにする。**「次はここ」などの部位の提案や、ローテーションの指示はしない。**
  - 選択肢は **言葉だけ** にする。猫の体のイラスト・針を刺す位置の図・動画は付けない（手技の指導にあたりうるため。ロシアン V3-8）。
- **アプリが推奨量を示したり、体重から計算したりはしない。**
- 前回の値は「前回 100 mL（11/8）」のように **日付つきの参考表示** にする。前回の値を量の欄に入れる場合も、保存前に値が見える状態を保つ（ロシアン #5）。
- 設定画面（S-07）に「指示された量が変わったら、ここを更新してください」という趣旨の導線を置く（文言は仮）。
- 量の変更の履歴をレポート（F-07）に載せる。
- 初回は量の欄を空欄にし、「獣医師に指示された量を入力してください」と添える（文言は仮）。
- 量の入力チェック（仮。`07` の Q-08）：**入力ミス（桁違い）の防止だけ** を目的にする。上限は臨床的な量とは無関係な値にする（例：3桁を超える値。値は仮）。根拠も「入力ミス防止のため」とする（ロシアン #6）。
  - 表示の案：「入力された量は 1000 mL です。このまま保存しますか？」
  - ⚠️ 「多すぎます」「危険」「獣医師に確認してください」などの評価語は使わない。
- リマインダー（F-06）の通知から、そのまま「やった」を記録できる。

### F-05 投薬の記録 ⚠️
- 猫ごとの「お薬リスト」を飼い主さんが登録する。
  - 名前：**製品名の候補リスト（F-26）から選ぶか、自由入力**（例：「白い錠剤（朝）」でもよい）。リストにない薬も、必ず自由入力で登録できる。
  - 形（錠剤／粉薬／液体／ペースト／その他）、回数・時刻（任意）、メモ
  - 量（錠数など）は飼い主さんが入力する。候補リストから選んでも、量・回数の初期値は入れない。
- 記録：飲めた／一部飲めた／飲めなかった／吐き出した ＋ メモ。
- 製品名の候補リストの条件は F-26 にまとめる（ユーザー決定 Q-09：候補リストを作る）。
- 二重投与の防止：同じ薬が同じ時間帯にすでに「飲めた」で記録済みの場合、「今朝 8:05 に記録済みです」と事実だけを表示する（判断や警告の表現にはしない）。「それでも記録する」「やめる」は **同じ大きさの選択肢** にし、片方を強調しない（ロシアン #8）。

### F-06 ケアのリマインダー
- 補液・投薬ごとに、飼い主さんが時刻と頻度（毎日／◯日おき／曜日指定）を設定する。
- 通知の例：「むぎちゃんのお薬の時間です」（文言は仮。ロシアンのレビュー対象）。
  - **せかさない**：再通知は最大1回まで（仮）。「急いで」「忘れています」などの表現は使わない。
- 通知のボタン：「やった」→ 記録する／「あとで」→ 30分後（仮）／開く。
- 夜間に鳴らさない時間帯を設定できる（F-11）。
- 通知の内容を隠す設定（F-24）：ロック画面には「ケアの時間です」だけを表示する（ロシアン #21）。

### F-07 獣医師に見せるレポート（PDF） ⚠️
- 猫と期間（直近2週間／1か月／前回の通院から／任意）を選ぶ → プレビュー → 共有・印刷・保存。
- 構成（仮）
  1. 表紙：猫の名前、期間、作成日、注記（案：「このレポートは飼い主さんの記録をまとめたものです。アプリは内容の評価や判定をしていません。記録のない日・項目は『—』で示しています。」最終文言は監修獣医師と調整。ロシアン #1・#4）
  2. 体調の一覧表：日付ごとの食欲・飲水・尿・嘔吐・便・元気さ・体重
  3. 体重の推移（F-12 と同じ。基準線なし）
  4. 皮下輸液の記録：日時・量・様子、量の変更の履歴
  5. 投薬の記録：薬ごとの実施状況
  6. メモ欄：飼い主さんのメモと「先生に聞きたいこと」
- ⚠️ **アプリによる評価・要約（「総合評価」「要注意」など）は入れない**（ロシアン A-4）。
- ⚠️ **「記録なし」と「0回」を必ず区別する**（ロシアン #1）。
  - 未入力の日・項目は「—（記録なし）」と表示し、「0」や空欄にしない。
  - 回数の合計などの集計値には、**「記録のある日数 ◯/◯日」を必ず並べる**。
- ⚠️ 集計は **事実の集計だけ**（記録日数・回数の合計など）。**増減率・矢印（↑↓）・前の期間との比較は出さない**。「悪化傾向」などの解釈の言葉、評価の色も付けない（ロシアン #3。`07` の Q-10）。
- 「前回と同じ」でコピーして直さずに保存した記録は、小さな印と凡例で区別して表示する（Q-18 決定）。
- 表示する集計値の範囲は、監修獣医師（ユーザー）とロシアンに確認する（→ `07` の Q-10）。
- 1分以内に作れることを目標にする（→ `05` の NFR-PERF-02）。

### F-08 記録の振り返り
- カレンダー：記録した日に小さな点を付ける。**記録のない日に印は付けない**（責めない）。
- タイムライン：その日の記録を時刻順に表示する。編集・削除ができ、削除時は確認を出す。

### F-09 データの書き出し・バックアップ・削除
- CSV の書き出し（猫ごと・全体）。
- 機種変更時の引き継ぎ方式は未決（→ `07` の Q-04）。
- アプリ内から全データを削除できる。

### F-10 お休み・一覧から外す（第1弾）
> ユーザーの決定（Q-11）により、見送り専用の機能は第2弾（F-25）に回しました。ただし、猫を亡くしたあとも補液や投薬のリマインダーが鳴り続けるのを防ぐため、第1弾にも次の **汎用の機能** を残します（Q-11b 決定）。

- **お休み**：猫ごとに、その猫の通知（リマインダー）を **すべて、ただちに** 止める。**理由は聞かない。**
  - 止め方の **初期値は「再開するまで」**。期間を指定することもできる（ロシアン V3-1。重大度：高）。
  - 期間を指定した場合も、**期間が終わっても通知を自動では再開しない**。猫を亡くした飼い主さんが期間つきで止めた場合に、亡くなった子のリマインダーが鳴り始めるのを防ぐため。
  - 期間が過ぎたあと、**アプリを開いたときに画面の中だけで** 「通知のお休みの期間が過ぎました。再開しますか？」と聞き、「再開する」「このまま止めておく」「一覧から外す」を **同じ大きさで** 並べる（文言は仮）。
  - **期間の終了をプッシュ通知で知らせない。**
- **一覧から外す**：猫をホームの一覧と記録対象から外す。
  - その猫の通知もすべて止まる。
  - 記録は削除しない。設定の「一覧から外した猫」から、閲覧・レポート作成・書き出し・一覧に戻すができる。
  - **理由は聞かない**（入院・譲渡・見送りなど、外す理由は人それぞれのため）。
  - 誤操作に備えて、いつでも一覧に戻せる。
- 文言は中立的にする。例：「通知をお休みする」「一覧から外す」。死や見送りを前提にした言葉は、第1弾の画面には出さない（仮）。

#### 見送り後の配慮のうち、第1弾にも関わるもの（ロシアン #12）
第1弾では、アプリはどの飼い主さんが猫を亡くしたかを知りません。そのため、**全員に対して** 次のことを守ります。
1. 再利用の呼びかけ（プッシュ・メール）、アンケートの通知を出さない。
2. 「1年前の今日」「記録をはじめて◯日」など、**記念日を自動で知らせる機能は作らない**。
3. 一定期間記録がないことを理由に、自動で一覧から外したり、見送りを想定した案内を出したりしない。
4. ストア評価の依頼は、①お休み中の猫・一覧から外した猫が **1匹でもいる** 人には出さない、②出す場合も OS 標準の依頼を最小限の回数にし、記録の直後など負担の少ない場面に限る（仮）。
   - アンケートは、第1弾では **全員に** 出さない（上の1）。
5. 一覧から外した猫を、ほかの猫の画面・レポートで比べない。

### F-25 見送り・思い出（第2弾）
- 猫のプロフィールから「見送った」を選べる。その猫の通知と広告を **ただちに** 止める（NFR-ADS-05）。
- 記録は削除せず、「思い出」として閲覧・PDF 化・書き出しができる。記録を消すかどうかを急がせない。
- **見送った猫が1匹でもいるユーザーには、ストア評価の依頼もアンケートも出さない**（ロシアン v2 再レビュー A）。ほかに記録中の猫がいても同じ。
- **第1弾の機能との関係**：
  - 「お休み」は一時的な通知の停止、「一覧から外す」は理由を問わない整理で、どちらも見送りを意味しない。第2弾では、一覧から外した猫を「見送った」に切り替えられる（逆に「見送った」を取り消すと、一覧から外した状態に戻る）。
  - ストア評価の依頼・アンケートを出さない対象は、「見送った猫がいる人」（第2弾）と「お休み中の猫・一覧から外した猫がいる人」（第1弾から）の **両方** とする。
- **見送り後に、しないこと**（ロシアン #12）：再利用の呼びかけ・アンケート・ストア評価の依頼を出さない／記念日の自動通知をしない（作る場合も本人がオンにしたときだけ）／理由・死因を聞かない（日付は任意）／ほかの猫と比べない／記録がないことを理由に自動で見送り扱いにしない。
- **言葉の選び方**（ロシアン #13）：「見送った」「思い出」のような中立的な言葉。「虹の橋」「天国」「お空」などは使わない。お悔やみは短い1文（案：「これまでの記録は、ここに大切に残しています。」）。明るいキャラクターや演出を出さない。最終文言は監修獣医師と決める。
- 第1弾の「一覧から外した猫」を、あとから「見送った」に切り替えられるようにする。
- 誤操作に備えて、「見送った」はあとから取り消せる。

### F-11 設定・見やすさ
- 文字サイズ（標準／大／特大）、通知の時間帯、ダーク表示、データ管理（F-09）、お問い合わせ。

### F-12 体重の推移グラフ ⚠️
- 体重だけの折れ線グラフ（期間切り替え：1か月／3か月／全期間）。
- **基準線・目標線・色分け・「減少しています」等のコメントは付けない**。
- 縦軸の幅に下限を設ける（仮：最小でも ±0.5 kg の幅。値は監修獣医師と決める → `07` の Q-19）。小さな変化が急な下落に見えて、不安をあおらないようにする（ロシアン #9）。
- 線の色は中立にする。減少率などの計算値は出さない。ホームには常に表示しない。

### F-13 次回の通院日メモ
- 日付を1つだけ登録し、ホームに「次の通院：11月20日」と表示する。通知はしない（第2弾の F-17 で対応）。

### F-26 製品名の候補リスト（薬：第1弾／フード：第2弾）⚠️
ユーザーの決定（Q-09）により、薬と療法食・フードの製品名の候補リストを作ります。ロシアン #7・#10 の条件を守ります。

**表示のルール**
- 載せるのは **製品名（と、必要なら剤形・メーカー名）だけ**。効能・用途・用量・対象の病気の説明は載せない。
- 並び順は **五十音順など機械的な順** にする。広告主の製品を上に出したり、目立たせたりしない。「おすすめ」「人気」などの表示はしない。
- 検索は、文字を入れると候補が絞り込まれる形式にする。最初から一覧を見せて選ばせない（仮。「アプリが掲載している＝推奨」と受け取られにくくするため）。
- リストから、広告・購入ページ・メーカーのサイトへの **導線を作らない**。
- 選んだ製品名を、広告の選択に使わない（NFR-ADS-04）。
- **リストにない製品は、必ず自由入力で登録できる**。飼い主さんが過去に入力した名前も、入力補完に出す。
- 療法食を選んでも、切り替えや別の製品をすすめる表示は出さない。
- 候補の近くに「かかりつけの獣医師に指示されたものを記録してください」という趣旨の一文を置く（文言はロシアンが確認）。
- 候補は **2文字以上入力して絞り込んだときだけ** 出す。一覧のカテゴリとして「人の薬」などを並べない。
- 候補を選んだ直後に、**剤形とメーカー名を必ず表示** し、名前の似た薬との取り違えに気づけるようにする。

**人体用医薬品の追加条件（必須）**（Q-24 決定。ロシアン V3-3）
- お薬リストの登録画面に、「獣医師から処方・指示された薬だけを記録してください。人の薬を自己判断で与えないでください。」という趣旨の一文を置く（文言は監修獣医師と調整）。
- 収録するのは、監修獣医師が「猫の CKD で処方されることがある」と確認したものだけにする。

**リストの作り方と保守（仮）**
| 項目 | 内容 |
|---|---|
| 薬の出典 | 動物用医薬品は、農林水産省 動物医薬品検査所が公開している動物用医薬品のデータベース（**要確認**：名称・利用条件）。猫の CKD で獣医師が処方することがある **人体用医薬品も含める**（Q-24 決定）。範囲は監修獣医師が決め、下の追加条件を **必須** とする |
| フードの出典 | 各メーカーの公式サイト・製品パッケージの公開情報。療法食は **「療法食」の一語だけ** で表記する。対象の病気（「腎臓病用」など）は、製品名に含まれている場合を除いて書き足さない（ロシアン V3-5）。フードのリストは第2弾の着手前にレビューする |
| 出典の利用条件 | **初版の作成前に**、各出典の利用条件（アプリへの同梱・再配布・商用利用の可否）を確認し、リストの版の記録に残す。収録するのは製品名（と剤形・メーカー名）だけで、説明文や画像は転載しない（ロシアン V3-4） |
| 収録範囲 | 猫の CKD のケアで使われることが多いものに絞る（監修獣医師が範囲を決める）。網羅はめざさない |
| 作成・更新 | **ブリショーが案を作る** → **監修獣医師（ユーザー）が内容を確認** → **ロシアンがレビュー** → 開発担当がアプリに収録（Q-25 決定） |
| 更新の頻度 | 3か月ごと（仮）。販売終了・名称変更があれば、次の更新で反映する |
| 配信方法 | リストはアプリに同梱し、オフラインでも使えるようにする。更新はアプリのアップデートで配信する（端末内保存の方針 Q-04 に合わせる。仮） |
| 販売終了の扱い | リストから消しても、すでに登録された名前と記録はそのまま残す |
| 広告主との関係 | 広告主はリストの収録・並び順に関与できない。広告主との契約にも明記する（NFR-ADS-10） |
| 記録 | リストの版・更新日・出典を記録し、アプリ内で「リストの更新日」を表示する |

## 3. 機能詳細（第2弾以降・要点のみ）

- **F-14 療法食・フード量** ⚠️（ロシアン #10）
  - フード名は **候補リスト（F-26）から選ぶか、自由入力**（Q-09 決定）。
  - フード名の記録画面・入力補完から、広告や購入リンクへの導線を作らない。
  - 入力されたフード名を、広告の選択に使わない（NFR-ADS-04）。
  - 療法食の名前を記録しても、切り替えや製品をすすめる表示は出さない。
- **F-15 写真記録**：体調記録に写真を最大3枚まで（仮）添付できる。写真は端末内に保存（仮）。
- **F-16 検査値の記録とグラフ** ⚠️⚠️（ロシアン A-1 を反映）
  - 手入力。検査機関によって単位が異なるため、単位は入力時に選ばせる。
  - アプリは **固定の基準範囲を持たない**。**IRIS のステージ境界線を引かない。ステージを自動で計算しない。**
  - 基準範囲は、飼い主さんが **検査結果の用紙から写して入力した値だけ** を、中立的な色の帯で表示できる（任意）。
  - 範囲外の値にも、赤字・警告アイコン・「高い／低い」「悪化」などのラベルを付けない。
  - ステージは「獣医師から伝えられたステージ」として、日付つきで任意に入力できる欄にする。アプリの動作（表示・通知・広告）には使わない。
  - 検査値の画面には広告を出さない（NFR-ADS-01）。
  - 第2弾の着手前に、あらためてロシアンのレビューを受ける。
- **F-17 通院予定**：予定の登録・前日の通知・「先生に聞きたいこと」メモ。メモはレポートに転記できる。
- **F-18 家族共有**：クラウド同期とアカウントが前提になる。個人情報・同意の設計を見直す。
